## 2. 协作回路

四件套，缺一不可：

1. **任务卡**：队长 TaskCreate 建卡（标题 + 验收标准 + owner）→ 成员认领置 in_progress → 只做卡范围内的事 → 产出落盘 → 验收 → 归档置 completed。
2. **留言板**：`team-board.txt`，`[YYYY-MM-DD HH:MM] 代号: 内容` 只追加不改；队长约 2 分钟巡检一次；阻塞标【阻塞】；成员间可直接喊话，不绕队长。
3. **三段式汇报**（≤150 字）：结论（做完了/卡在哪）→ 产出路径 → 风险与待决策。
4. **升级规则**：需求不清 / 方案分歧两轮 / 超职责 / 有风险——四种情况必须停下来问队长；实现细节自己拍板，汇报里提一句即可。

完成定义（DoD）三条同时满足：**可验证**（逐条对照验收标准）、**有产出**（文件已落盘）、**有回报**（卡置 completed + 汇报已发）。

## 4. 事故与教训（四条均来自真实记录）

1. **docs spawn 429 限流**（09:52）：环境并发上限约 2–3 个 agent，docs 的 spawn 被队列打回，非成员之过。
   → 处置：队长直接代搭骨架（LICENSE/.gitignore/CONTRIBUTING/README 四件套），docs 主战场移驻 R3。
   → 沉淀：**后续轮次一律串行/双人编组**，不超发并发。
2. **scout 500 故障 + 汇报不实**（10:05–10:22）：spawn 因模型提供方 500 中断（跑了 8 分 44 秒）；且其汇报「RESEARCH.md 已产出」时文件实际未落盘（写入失败）。
   → 处置：队长亲自完成 RESEARCH.md，scout 留言发现原文存档并标「待验证」，岗位保留到 R4 交叉核验。
   → 沉淀：**DoD 自检铁律——报「已产出」前必须 Read/ls 验证文件真实存在**；关键路径不等待故障成员，队长代打保节奏。
3. **官方 MCP 文档 404**（architect 发现）：workbuddy.cn 无 MCP 集成页，schema 无官方口径。
   → 处置：采信同厂 CodeBuddy 官方《MCP 集成》并全文标 `[假设]`；队长批准该口径，dev 首步实测回填，R4 tester 再交叉核验。
   → 沉淀：**同厂口径可采信但假设必须显式标注 + 实测闭环**，先跑通再优化。
4. **规格书包名 404（生态漂移）**（R3，队长实测）：ASSET-SPEC §2 原列的 `server-fetch`/`server-time` 两个 npm 包实测不存在（官方参考实现已调整）；CI 脚本首跑还抓到自身注释 bug（`*/` 提前终止块注释）。
   → 处置：剔除 404 包，换实测存在的 filesystem/memory/time-mcp 三台 stdio + github 远程；ASSET-SPEC §2 加勘误段；脚本 bug 修复后复跑通过。
   → 沉淀：**规格里的包名必须实测才能进模板**——[假设] 回填机制再次兑现；套用任何第三方清单前先 `npm view` 复核版本。

## 5. 复现指南（用同样编成跑你自己的项目）

1. **建档案再开工**：team/TEAM.md（章程+花名册）、协作规范、验收标准、留言板，一次成型。
2. **角色按需裁剪**：核心是不可少的四角——队长（决策）、架构（设计）、开发（施工）、测试（验收）；调研/文档/逆向按项目规模兼任。
3. **轮次推进**：R1 调研清点 → R2 架构设计 → R3 资产构建 → R4 验收 → 推送；每轮产出先落盘再汇报。
4. **并发纪律**：agent 并发控制在 2–3 个，串行/双人编组；关键路径成员故障时队长代打，不空等。
5. **验收闭环**：单人小产出队长核对，跨成员集成拉测试联合挑刺；假设项标注 → 实测回填 → 复核转正。
6. **教训入库**：每次事故按「现象 → 处置 → 沉淀规则」三段记入本文档，规则进协作规范，下个项目直接受益。
